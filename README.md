# Система управления релизами

Консольное приложение для учёта продуктов и управления релизами:
проверка готовности версии, публикация в окружение и отмена выпуска.

На ПР1 был реализован сценарий проверки одного релиза. На ПР2 этот
сценарий сохранён в функциях `get_release_status`, `can_publish_release`,
`classify_version` и `describe_release_deadline`. На ПР3 сущности
предметной области представлены классами, а данные хранятся как
коллекции объектов.

## Возможности

- просмотр, поиск, добавление и удаление продуктов;
- просмотр, поиск, добавление и удаление разработчиков;
- просмотр, поиск и добавление задач, смена статуса;
- просмотр, поиск и добавление релизов;
- проверка готовности к публикации;
- публикация релиза в `test`, `staging` или `production`;
- отмена запланированного релиза;
- статистика по статусам релизов.

## Основные классы

### Entity

Базовый класс именованной сущности. Атрибуты: `id`, `name`.
Методы: `matches()`, `to_data()`, `__str__()`.
От него наследуют `Product` и `Developer`.

### Product — продукт

Объект `Product` представляет программный продукт.

Основные атрибуты: `id`, `name`.

Основные методы:

- `validate_name()` — проверка названия (`@staticmethod`);
- `from_data()` — создание из словаря JSON (`@classmethod`);
- `__str__()` — строковое представление продукта.

### Developer — разработчик

Объект `Developer` представляет участника команды.

Основные атрибуты: `id`, `name`, `role`.

Основные методы:

- `from_data()` — создание из словаря JSON;
- `to_data()` — данные для JSON;
- `__str__()` — строковое представление разработчика.

### Release — релиз

Объект `Release` представляет конкретную версию продукта.
Он хранит ссылку на объект `Product`, а не только `product_id`.

Основные атрибуты: `id`, `product`, `version`, `environment`,
`tests_passed`, `approvals_count`, `required_approvals`,
`is_hotfix`, `release_date`, `status`.

Основные методы:

- `can_publish()` — проверка готовности к публикации;
- `publish()` / `cancel()` — изменение состояния объекта;
- `classify()` / `describe_deadline()` / `readiness` — правила ПР1;
- `from_data()` / `to_data()` — преобразование JSON;
- `__str__()` — карточка релиза.

Свойства `status`, `is_cancelled`, `is_active` и `readiness`
доступны через `@property`. Отмена не удаляет объект из коллекции.

### Task — задача

Объект `Task` связывает разработчика, продукт и необязательный релиз.

Основные атрибуты: `id`, `title`, `developer`, `product`,
`release`, `status`.

Основные методы:

- `set_status()` — смена статуса задачи;
- `from_data()` / `to_data()` — преобразование JSON;
- `__str__()` — строковое представление задачи.

## Взаимодействие объектов

```text
Task
├── developer → Developer
├── product   → Product
└── release   → Release | None
                 └── product → Product
```

Данные связанных объектов доступны через атрибуты:
`release.product.name`, `task.developer.name`, `task.release.version`.

В памяти используются коллекции `list[Product]`, `list[Developer]`,
`list[Release]`, `list[Task]`. В JSON связи хранятся идентификаторами.

## Основные операции

### Работа с продуктами

- добавление продукта;
- поиск по названию;
- сортировка;
- удаление, если нет активных релизов;
- просмотр списка.

### Работа с разработчиками

- создание разработчика;
- поиск по имени или роли;
- удаление, если нет открытых задач;
- просмотр списка.

### Работа с релизами

- создание релиза, связанного с объектом Product;
- проверка готовности методами объекта;
- публикация и отмена (состояние меняется, объект остаётся);
- поиск по версии и статистика.

### Работа с задачами

- создание задачи со ссылками на объекты;
- поиск по названию;
- смена статуса;
- просмотр списка.

## Хранение данных

Данные приложения хранятся в JSON-файлах:

- `data/products.json`;
- `data/developers.json`;
- `data/releases.json`;
- `data/tasks.json`.

При загрузке словари JSON преобразуются в объекты `Product`,
`Developer`, `Release` и `Task`. При сохранении объекты
преобразуются обратно в данные. Для связи релиза с продуктом
и задачи с разработчиком в JSON используются идентификаторы.

## Назначение модулей

### `main.py`

Точка входа. Отвечает за запуск меню, ввод пользователя и
организацию сценариев. Коллекции словарей предметной области
не хранит.

### `models/products.py`

Класс `Product` и функции работы с коллекцией продуктов.

### `models/developers.py`

Класс `Developer` и функции работы с коллекцией разработчиков.

### `models/releases.py`

Класс `Release`, функции ПР1 и операции над коллекцией релизов.

### `models/tasks.py`

Класс `Task` и функции работы с коллекцией задач.

### `storage.py`

Загрузка и сохранение данных. Выполняет преобразование
JSON → объекты Python и объекты Python → JSON.

### `utils.py`

Вспомогательные функции: `input_int()`, `input_date()`,
`input_bool()`, `input_environment()`.

### `tests/`

Автоматизированные тесты pytest.

## Требования

- Python 3.x;
- pytest;
- flake8;
- black;
- isort.

Установка зависимостей:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Запуск программы

```bash
python main.py
```

После запуска отображается главное меню.

## Тестирование

```bash
pytest -v
```

Тесты проверяют создание и работу объектов `Product`, `Developer`,
`Release` и `Task`, методы классов, связь релиза с продуктом,
создание и отмену релиза, смену статуса задачи.

## Назначение и аудитория

Приложение предназначено для менеджеров релизов, инженеров DevOps,
разработчиков и тестировщиков, которые согласовывают выпуск версии.

## Предметная область

Управление релизами — подготовка, согласование и публикация новой
версии продукта. Публикация в production запрещена, пока тесты
не пройдены или не набраны согласования. Отменённый релиз не
удаляется: он остаётся в коллекции, но больше не публикуется.
