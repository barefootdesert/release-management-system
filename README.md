# Система управления релизами

Консольное приложение для учёта продуктов и управления релизами:
проверка готовности версии, публикация в окружение и отмена выпуска.

На ПР1 был реализован сценарий проверки одного релиза «Платёжный шлюз»
версии 2.1.0. На ПР2 этот сценарий сохранён в функциях `get_release_status`,
`can_publish_release`, `classify_version` и `describe_release_deadline`
и используется для набора продуктов и релизов, которые хранятся в JSON.

## Возможности

- просмотр, поиск, добавление и удаление продуктов;
- просмотр, поиск, добавление и удаление разработчиков;
- просмотр, поиск и добавление задач, смена статуса;
- просмотр, поиск и добавление релизов;
- проверка готовности к публикации;
- публикация релиза в `test`, `staging` или `production`;
- отмена запланированного релиза;
- статистика по статусам релизов.

## Структура проекта

- `main.py` — точка запуска и меню;
- `products.py` — работа с продуктами;
- `developers.py` — работа с разработчиками;
- `tasks.py` — работа с задачами;
- `releases.py` — работа с релизами, включая функции из ПР1;
- `storage.py` — загрузка и сохранение JSON;
- `utils.py` — ввод чисел, дат и логических значений;
- `data/` — JSON-файлы данных;
- `tests/` — автоматизированные тесты pytest.

## Формат данных

Продукты хранятся в `data/products.json` (`id`, `name`).
Разработчики — в `data/developers.json` (`id`, `name`, `role`).
Задачи — в `data/tasks.json` (`title`, `developer_id`, `product_id`,
`release_id`, `status`: `todo` / `in_progress` / `done`).
Релизы — в `data/releases.json` (версия, окружение, тесты, согласования,
дата и статус `planned` / `published` / `cancelled`).

## Требования

- Python 3.x;
- pytest;
- flake8;
- black;
- isort.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Проверка качества кода

Линтер показывает замечания по PEP 8. Если всё в порядке, вывода нет:

```bash
flake8
```

Форматтер сам правит пробелы, переносы и кавычки. Это не меняет
логику программы, только внешний вид кода (урок Практикума
«Оформление кода, линтеры и форматтеры»):

```bash
black .
isort .
```

Проверить, что код уже отформатирован, без записи в файлы:

```bash
black --check .
isort --check .
```

## Назначение и аудитория

Приложение предназначено для менеджеров релизов, инженеров DevOps,
разработчиков и тестировщиков, которые согласовывают выпуск версии.

## Предметная область

Управление релизами — подготовка, согласование и публикация новой
версии продукта. Публикация в production запрещена, пока тесты
не пройдены или не набраны согласования.

## Основные сущности

- **Продукт** — программный продукт, для которого готовится выпуск.
- **Разработчик** — участник команды, которому назначают задачи.
- **Задача** — работа по продукту, связанная с разработчиком и релизом.
- **Релиз** — конкретная версия с датой, статусом и признаком hotfix.
- **Окружение** — место публикации: `test`, `staging` или `production`.
- **Согласование** — подтверждение готовности ответственным сотрудником.
- **Сборка** — результат проверки тестами.
