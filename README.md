# Система управления релизами

## Назначение

Консольное приложение для сопровождения выпуска программных продуктов:
фиксация версии, проверка готовности релиза и решение о публикации
в выбранное окружение (тестовое, предпрод или продуктивное).

На текущем этапе программа выполняет один законченный сценарий —
оценку возможности публикации конкретного релиза. В дальнейшем
приложение станет веб-сервисом, в котором команды смогут планировать
релизы, согласовывать их и отслеживать статусы.

## Целевая аудитория

- менеджеры релизов и руководители команд разработки;
- инженеры DevOps и специалисты по выкладке;
- разработчики и тестировщики, участвующие в согласовании выпуска;
- владельцы продукта, которым нужна прозрачная картина готовности версии.

## Предметная область

Управление релизами — это процесс подготовки, согласования и публикации
новой версии программного продукта. Релиз связан с продуктом, целевым
окружением, результатами тестов и необходимым числом согласований.
Публикация в продуктив запрещена, пока тесты не пройдены или не набраны
согласования. Предрелизная версия (`0.x.x`) и обычный выпуск
обрабатываются по разным правилам.

Предметная область естественно раскладывается на сущности с связями,
пользовательскими ролями и операциями создания, просмотра, изменения
и удаления данных — это подходит для последующей реализации на Django,
REST API и развёртывания в Docker.

## Основные сущности

- **Продукт** — программный продукт, для которого готовится выпуск.
- **Релиз** — конкретная версия продукта с датой, статусом и признаком hotfix.
- **Окружение** — место публикации: `test`, `staging` или `production`.
- **Согласование** — подтверждение готовности от ответственного сотрудника.
- **Сборка** — результат проверки тестами, влияющий на допуск к публикации.

## Основные функции

- определение текстового статуса релиза по тестам и согласованиям;
- проверка, можно ли публиковать релиз в выбранное окружение;
- классификация версии (предрелизная, minor или patch);
- оценка срока до запланированной даты выпуска;
- просмотр списка релизов и фильтрация по статусу и окружению (планируется);
- создание, изменение и отмена релиза (планируется);
- согласование релиза пользователями с разными ролями (планируется);
- публикация релиза и фиксация истории выкладок (планируется).

## План развития

На следующих этапах планируется:

- расширить консольный сценарий коллекциями, функциями и модулями (ПР2);
- описать сущности предметной области в виде классов (ПР3);
- разработать веб-приложение на Django;
- подключить базу данных и реализовать модели продукта, релиза и окружения;
- реализовать пользователей, регистрацию и разграничение доступа;
- реализовать формы создания и изменения релизов;
- разработать REST API;
- покрыть ключевые сценарии автоматизированными тестами;
- контейнеризировать приложение;
- настроить CI/CD.
