## 3. Индивидуальный проект

- **Название проекта:** Система управления релизами
- **Предметная область:** подготовка, согласование и публикация версии программного продукта в выбранное окружение (`test`, `staging`, `production`). Основные сущности: продукт, релиз, окружение, согласование, сборка.
- **Реализованный на ПР1 функционал:** один законченный консольный сценарий проверки готовности релиза «Платёжный шлюз» версии `2.1.0` к публикации в `production`. В `main.py` реализованы четыре функции из README.md:
  - определение текстового статуса релиза по тестам и согласованиям;
  - проверка допуска к публикации в выбранное окружение;
  - классификация версии (предрелизная, minor или patch);
  - оценка срока до запланированной даты выпуска.
- Использованы конструкции ПР1: простые типы данных, операции, преобразование типов (`int`), ветвления `if`/`else`, функции и импорт модуля `datetime`. Коллекции, циклы и классы не применялись.
- **Ссылка на Git-репозиторий:** https://github.com/barefootdesert/release-management-system

Структура репозитория соответствует требованиям ПР1: `README.md`, `.gitignore`, `main.py`.

## 4. Результат работы

В результате выполнения ПР1:

- настроено рабочее окружение: установлен Python 3.14, IDE (VS Code / Cursor), Git и виртуальное окружение;
- создан Git-репозиторий индивидуального проекта, результат зафиксирован коммитом и отправлен в удалённый репозиторий;
- подготовлен файл `README.md` (назначение, целевая аудитория, предметная область, сущности, функции, план развития);
- реализован начальный программный сценарий; программа корректно определяет статус «готов к публикации» и разрешает выкладку при пройденных тестах и полном наборе согласований;
- выполнена отладка: установлены точки останова в функции `get_release_status`, программа запущена в режиме отладки, выполнен пошаговый проход и просмотрены значения переменных. Для поиска дефекта намеренно уменьшалось число согласований, после чего отладчиком подтверждалась причина смены статуса на «ожидает согласования».
